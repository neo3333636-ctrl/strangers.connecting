# 設計:官網「走進一間有氛圍的餐廳」互動改造

- 日期:2026-06-05
- 站別:`strangers.connecting`(strangersconnecting.com,純靜態 / GitHub Pages,vanilla HTML/CSS/JS,無 build step)
- 參考:TRUE(set-builder agency 站)的**動作文法**,非其冷色視覺

## 核心隱喻

網站 = 一間餐廳。

- 捲動 = 往店裡深處走
- 點擊 = 穿過一道門進到下一個空間

借 TRUE 的互動語言(慣性捲動、遮罩揭示、穿門推進、磁吸、主色啟動),但視覺 100% 維持既有暖色品牌、Fraunces 襯線、真實照片。動畫情緒是「一個夜晚慢慢展開 / 一段連結正在形成」,不是技術算圖。

**在軌道上往前(on rails)**——設計好的路徑,使用者只負責往前,不是自由行走 3D。

## 已確認的決策

1. **範圍**:整站互動語言一起規劃。
2. **品牌**:保留現有暖色品牌,不往 TRUE 的冷色 / 編輯感靠。
3. **「往前走」技術**:方法 A —— 深度分層推進(2.5D scale-through),on rails。
   - hero 用現有 `images/how-doorway.jpg`(門口照,已具縱深),不依賴補拍影片。
   - 不採方法 B(影片擦洗)做 hero;不採方法 C(WebGL 3D 飛行)—— 對純靜態站划不來,明確不做。
4. **子頁範圍**:首頁完整 journey;子頁(about / faq / how-to-join / rules)用穿門轉場進場 + 內容輕量揭示(閱讀優先,不 scroll-jack);法律頁(privacy / terms)只繼承平滑捲動 + 轉場,不加花俏。

> 「門口 → 走進去 → 入座」的縱深序列素材已大致齊備;切圖層由程式 / CSS 處理,不需手動 Photoshop。

## 技術骨架(零打包,維持純靜態)

CDN 直接掛,無 build step:

| 用途 | 工具 |
|---|---|
| 慣性平滑捲動(整站地基) | Lenis |
| 捲動驅動縮放 / 視差 / pin / 區塊揭示 | GSAP + ScrollTrigger |
| 標題逐詞遮罩上滑 | SplitType |
| 磁吸按鈕、游標暖光指示、穿門轉場 | 手寫 vanilla JS |
| 跨頁穿門轉場 | View Transitions API(支援時)+ JS 遮罩後備 |

- 新增動畫 JS / CSS 抽成 `assets/journey.js`、`assets/journey.css`,不再塞進 145KB 單一 `index.html`。
- 全程包 `prefers-reduced-motion`;手機降級為單純淡入,穿門縮放在小螢幕簡化。

## 首頁動線(每個區塊 = 一個空間)

只在 2–3 個有意義的「門檻」用穿門推進(克制使用,避免動暈):

```
① 門口 / HERO   how-doorway.jpg 切成 前景門框+人 / 玻璃 / 後景暖廳;
                捲動時後景暖廳放最快 → 被吸進門裡;Fraunces 標題遮罩上滑
   ↓【穿門】
② 吧台 / 品牌理念  進到店內、暖光;理念逐行揭示;環境元素輕微視差
   ↓
③ 一桌一個故事 / 活動  活動卡 = 一張張桌子,逐一揭示;hover 抬起+暖光(磁吸)
   ↓【入座】
④ 桌邊細節        room-01 桌邊特寫;FAQ / 加入方式 預告
   ↓
⑤ 出門 / CTA      報名 / LINE 加入,帶「走出店門」收尾動作
```

> 注:此動線是把**現有首頁區塊**重新編排成「房間」順序,沿用既有內容,不重寫文案。

## 導覽 / 跨頁

- nav 指向**頁內區塊** → Lenis 平滑捲到該「房間」。
- nav 指向**子頁** → 穿門轉場:暖色簾幕往前推蓋住畫面 → 換頁 → 揭開。點一下像「走到下一間」。
- 跨頁優先用 View Transitions API(cross-document),不支援的瀏覽器走 JS 遮罩後備,並優雅降級為一般跳轉。

## 子頁(輕量)

- 繼承平滑捲動 + 穿門進場。
- 內容區塊:簡單依序淡入上移,閱讀優先,不 scroll-jack。
- 法律頁(privacy / terms):只繼承平滑捲動 + 轉場,零額外編排。

## 動作細節(借 TRUE 語法、調暖)

- 磁吸按鈕(CTA、nav 藥丸)。
- 游標暖光指示——互動元素旁的小圈,燭光暖色而非冷灰。
- 主色只在互動時被點亮(hover 填色 / 連結底線擦過);沿用既有品牌色,挑一個「燭光暖」當互動主色。
- 標題 Fraunces 逐詞遮罩上滑(載入 + 進區塊時)。

## 效能

- 壓縮 hero / room 圖、產生對應尺寸;下方圖片 lazy-load。
- 穿門素材保持輕量。
- 目標中階手機順暢,撐不住則優雅降級。

## 誠實的限制 / 風險

- **on rails**,非自由行走 3D。
- 穿門**克制使用**,避免動暈。
- 跨頁 View Transitions 各瀏覽器支援不一 → JS 後備 + 降級。
- iOS 慣性捲動 + 圖層縮放效能需實測;若 hero 穿門在低階機掉幀,簡化縮放層數。

## 建議施作順序(先驗證再鋪開)

1. **HERO 原型**(穿門推進 + Lenis + 標題揭示)—— 讓使用者親手感受對不對味 ← 驗證關卡
2. 首頁其餘 journey 區塊(②–⑤)
3. nav 穿門轉場 + 子頁進場
4. 子頁內容揭示 + 法律頁
5. 收尾:磁吸 / 游標 / reduced-motion / 手機 / 效能 QA

## 需要使用者後續提供(非阻塞,可選)

- (可選,讓 hero 更強)一支鏡頭緩慢往前走、穩定、~15–30s 的餐廳 walkthrough 影片 —— 未來可升級為方法 B。
- (建議)再 2–3 張具縱深(門 / 走道 / 消失點)的照片,當子頁穿門門檻變化。
- 現有照片的高解析原檔(放大穿門不糊)。

## 成功標準

- 首頁從上往下捲,主觀感受像「一路走進餐廳深處」;至少在 hero → 店內有一次明確「穿門」。
- 點 nav 進子頁有「往前走到下一間」的連貫轉場,而非硬跳轉。
- 桌機與中階手機皆順;開啟 reduced-motion 時內容完整可讀、無暈眩動畫。
- 視覺維持暖色品牌,無 TRUE 的冷調。
